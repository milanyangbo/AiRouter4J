# 13: 每实例运行时状态归谁 —— 注册表是唯一持有者，还是 `observe` / `transport` 各存一份

**What to build:** 把「每实例运行时状态放在哪」这件事**裁决掉**，让文档与代码说同一句话。
本票主要是裁决 + 写文档，代码改动取决于裁决结果。

来源：两轴 code review（2026-10-28，固定点 `eedaff6`）的 Standards 轴第 1 条（判为偏硬），
加上 Spec 轴第 5 条（EWMA 条目的清理时机）。

- 根 `GLOSSARY.md`「注册表」条：*"「配置 → 运行时对象」的**唯一**持有者：服务、实例、形态，
  以及挂在实例上的熔断状态、**延迟样本**、健康登记。其它包不自己缓存这些东西"*；
  `registry/package-info.java` 重复了同一句（*"而不是各自存一份映射"*）
- 现状是两张表在注册表**之外**，都按 instanceId 建键：
  `observe/LatencySamples` 的 `ConcurrentHashMap<String, Sample>` 与
  `transport/ActiveCallMeter` 的 `ConcurrentHashMap<String, AtomicInteger>`
- 这不是「谁写错了」，是**两处标准在打架**：票 10 按 ADR-0003（`select` 是纯函数、
  策略不许做 IO）把样本放 `observe`，而术语表那一句写的是另一套。
  票 10 已把它记进 Known gaps（待 `domain-modeling` 裁决）—— **本票就是那次裁决**
- 顺带一条**实现**缺口：票 10 的验收要「候选里消失的实例**不再参与**」，
  而 `LatencySamples.dropStaleEntries` 只按保留窗口（默认 10 分钟）清理。
  「不再产生结算」是这里唯一拿得到的「它已经不在了」的信号，
  但它与粘滞的形状不同 —— 粘滞是**发现不在候选当场丢掉**（`StickySelector`），
  这里是**十分钟之后**。两种形状各有代价，本票要挑一个并写明

## Acceptance criteria

- [ ] 裁决写进 `GLOSSARY.md` 与 `registry/package-info.java`，二选一：
      ① 每实例状态搬回注册表（那要回答「策略怎么拿到它而不做 IO」）；
      ② **改标准**：写明「注册表持有『配置 → 运行时对象』，而**观测到的**每实例状态由
      `observe` 持有、在途计数由 `transport` 持有」，理由指向 ADR-0003 的纯函数约束
- [ ] 改完之后两处文字与代码一致：`registry` 的 javadoc 不再声称自己是「唯一」，
      或代码真的搬回去（**二选一，不许留下两套说法**）
- [ ] EWMA 条目「不再参与」的时机被显式化：要么与粘滞同形（发现不在候选当场丢），
      要么在文档里写清「为什么按保留窗口就够」，并且**有一条断言钉着那个时机**
- [ ] `ActiveCallMeter` 的安置在同一份裁决里一并说明（它也是按实例的映射，
      不说明的话下一次 review 会再指一次）
- [ ] 术语表里不出现与实现相反的动词；改完通读 `GLOSSARY.md`「实例维度」那一节的其他条目，
      确认没有同类句子

## 测试

- 一条断言钉住 EWMA 条目「不再参与」的**时机**（不是钉住「迟早会丢」——
  保留窗口迟早会到，那种断言抓不住「十分钟」与「当场」的差别）
- 文档与代码的一致性没有自动判据：**本票的判据是下一次 review 不再指到同一条**。
