# ADR-0020：阶段排期与任务清单

- 状态：已接受
- 日期：2026-10-26
- 相关：[0001](./0001-scope-target-state-and-sequence.md) 第 5 节（三条顺序硬约束）

## 1. 排期原则

1. **先能跑，再铺开。** 阶段 2 结束就应该有一条真实请求穿过网关拿到响应 —— 之后再谈多实例与治理
2. **实例维度先于一切作用域类功能**（0001 第 5 节）。限流的作用域、规则的目标、失败转移换谁、配额的维度，全部以它为前提
3. **库就位之后再铺需要落库的能力。** 规则、配额、调用历史、厂商声明都要落库，所以持久化排在它们前面
4. **租户先于按租户记账的东西。** 认证（阶段 6）先于限流与配额，否则它们的 `client` 维度没有来源
5. **控制台最后**，且前置是管理面 API 契约已被契约测试钉住
6. 每阶段结束打一个 `baseline-<n>` tag：既是回滚点，也是差异类测试的基线

## 3. 各阶段细则

### 阶段 0 —— 构建骨架重建

**为什么第一件是它**：根 pom 与四个模块 pom 已在阶段 0 删除（`10c42a1`），现在没有任何可构建的东西。

- 重建 `pom.xml` ×5：根（packaging=pom）+ 四模块
- enforcer（版本、JDK 21、重复上界依赖、插件版本、禁止抑制文件）、checkstyle、spotbugs、surefire 分组
- `airouter-app` 的结构规则骨架：`StructuralRules` 九条 + `GuardsActuallyFireTest` + `EveryTestBelongsToAGateTest`
- 四个模块的目录与 `package-info.java`

**验收**：`./mvnw clean verify` 绿；故意违反一条结构规则 → 红（守门测试生效）。

### 阶段 1 —— core 领域模型与端口

Canonical 六型事件、CanonicalRequest/Response、GatewayError、两个端口、Outcome/OutcomeKind。

**验收**：core 依赖树里引入任一框架 → enforcer 判红；契约测试的目录骨架就绪（三目录 + 各 README）。

### 阶段 2 —— 第一个端到端

OpenAI 兼容 Face + Provider + SSE 传输 + 流式终态与结算（0005 全条）。

**验收**：真实的非流式与流式请求穿过网关拿到响应；`contract/` 与 `contract-stream/` 有 golden 样本；
上游不发 `[DONE]` → `Failed` 而不是成功；取消 → `CLIENT_CANCELLED` 且无事件。

### 阶段 3 —— 配置模型、注册表与形态工厂（实例维度之一）

服务 / 实例 / 形态三级模型、注册表（唯一持有者）、形态工厂、启动期校验、热重载不重建上下文。

**验收**：一个 Service 下两个实例并存且形态可不同；配置变更不丢在途流与熔断计数；
缺 `/v1` 或凭证 → 启动失败并指名具体实例。

### 阶段 4 —— 选择链与负载均衡（实例维度完成）

六步选择链落在 `routing` 一处；6 个纯函数策略 + 独立加权步骤 + 粘滞包装器；EWMA 样本来自 Outcome。

**验收**：策略可确定性断言（不起端点）；流式与非流式走同一条链（结构 + 端到端断言）；
新增形态不触碰 `faces` 与 `core`。

### 阶段 5 —— 持久化与迁移

JDBC 直写、Flyway 双方言（H2 + PG）、一套 store、表结构按消费方倒推、**依赖缺席是契约**。

**验收**：H2 与 PG 跑同一套迁移都能起来；DB 不在 / Redis 不在各有一条断言行为（不是「没崩就算过」）。

### 阶段 6 —— 认证、API Key 与租户标识

Key 只存哈希、入口统一校验、租户是限流/配额/缓存的隔离维度、精简 RBAC、凭据不透传下游。

**验收**：跨租户不串缓存；出网 Authorization 是实例自己的凭证；权限组件异常 → 拒绝。

### 阶段 7 —— 韧性

熔断（实例级、只读 Outcome、无锁、带 requestId 留痕）、失败转移（白名单 + 只结算最终一次）、
限流（四算法、四级作用域、Redis→本地、管理面同一内核）、响应缓存（默认关闭、含租户键、只非流式）。

**验收**：不可重试的 4xx 不换实例；取消不计入熔断；限流器挂了默认拒绝。

### 阶段 8 —— 规则引擎

六维度匹配、首命即止、命中统计持久化、无匹配默认拒绝、定义可持久化与可视化编辑（接口先行）。

**验收**：首命即止有断言；命中统计重启后仍在；规则写坏 → 拒绝加载并报出具体规则。

### 阶段 9 —— 配额

多维度 × 四窗口、预留 → 结算、Redis 主 + 本地降级、默认关闭、**fail-closed**。

**验收**：N 个并发同时到达时超额可被判定；Redis 不在时行为被断言。

### 阶段 10 —— 记录治理

三档（metadata / summary / full）、脱敏规则可配且失败拒绝记录、AES-256-GCM 全文、解密仅 ADMIN 且记审计。

**验收**：库里查不到明文；脱敏规则非法 → 拒绝记录；非 ADMIN 解密被拒。

### 阶段 11 —— 可观测

OTel 链路（不自研）、Micrometer 指标、慢查询按实例聚合、错误追踪、安全告警（出口只有指标 + 日志）、告警冷却共享。

**验收**：流式与非流式指标口径一致；取消单独计数且不进失败率；多副本下告警只触发一次。

### 阶段 12 —— 适配器补齐

Anthropic 原生形态、Gemini 原生形态、声明式 OpenAI 兼容厂商（配置 + 落库，支持运行时新增）。

**验收**：新增一个 OpenAI 兼容厂商**只改配置，不改 Java 文件**（有测试守）。

### 阶段 13 —— 多副本

Redis 事件广播（变更事件 + 版本号）、共享限流/配额计数、分布式锁（定时任务、告警冷却）。

**验收**：两个副本同时跑定时任务只有一个执行；锁丢失时的行为被断言。

### 阶段 14 —— C 深度

EWMA 参数调优、熔断自适应阈值、配额对账（预留与实际的差额分布）。**紧接 B，不得无限延后。**

### 阶段 15 —— D 控制台

管理面 API 契约测试 → 适配 legacy 的 Vue 3 页面（保留深/浅主题与中英双语）。

**验收**：每个页面组对应的 API 有契约测试；前端构建通过；本阶段不新增网关侧能力。

## 4. 优先级理由（为什么不是别的顺序）

| 有人会想先做 | 为什么不行 |
|---|---|
| 先做限流 | 没有实例维度时，`instance` 作用域无处安放，做出来是全局开关 |
| 先做控制台 | 页面需要的管理面 API 语义还没定，做出来的取数层要重写 |
| 先补齐 9 个适配器 | 厂商是配置，形态才是代码；先补厂商等于先写 6 个无差异的类 |
| 先做配额 | 配额按租户记账，租户来自认证；且它依赖 Redis 与库 |
| 先把表建全 | 表由消费方倒推。没有消费方的表，只能靠猜 legacy 的 20 张表 |

## 5. 打 tag 纪律

每阶段结束打 `baseline-<阶段号>`：既是回滚点，也是差异类测试的基线
（历史上 `SecondProviderTouchesNoFaceTest` 就依赖基线 tag，浅克隆会让它空过 —— CI 恢复时要 `fetch-depth: 0`）。
