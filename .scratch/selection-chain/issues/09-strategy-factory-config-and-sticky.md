# 09: 策略工厂、配置与粘滞包装器

**What to build:** 把「用哪个策略」从代码变成配置，并把**粘滞**做成包装器。

- **策略工厂**：按名取策略（`airouter.routing.strategy`）。
  未知名 → **启动失败并列出已登记的名字** —— 与形态工厂报「没有对应的构造器」时
  列出已登记形态同一理由：让运维自己改对一个字，而不是去翻代码
- **粘滞是包装器，不是第七种策略**（ADR-0011 (c)）。legacy 的 `StickyLoadBalancer`
  就是包装器，搬的时候必须保持这个形状 —— 搬成策略会丢掉「粘滞可与任意策略组合」这个性质

## Acceptance criteria

- [x] `SelectionStrategyFactory` 按名取策略；**未知名 → 启动失败并列出已登记的名字**
- [x] `airouter.routing.strategy` 绑定与校验：未知值**启动失败**（与上面同一条判据的两处入口，
      别只在一处拦）
- [x] 粘滞**包在任意策略之外**，键 = 自定义键，没有就退回 `callerId`
- [x] 粘滞命中、且它仍在候选里 → 直接用；不在了（被关掉、被第 ③ 步排除）→ 交给策略，
      并把新结果记回（不是报失败）
- [x] **`callerId` 缺失时粘滞失效是显式且被断言的行为** —— 定为**拒绝**（400
      `caller_identity_required`），不退化成每次换一个实例
- [x] 粘滞 + 随机、粘滞 + 轮询 都能稳定命中同一实例（两条接缝各一条断言）
- [x] 粘滞表**有界 + 惰性清理**：满容量挤掉最久没被用过的键；发现粘着的实例已不在候选里当场丢掉那条记录
- [x] 两个名字登记进工厂（`random` / `round-robin`），四个留票 10；
      「未知名列出已登记名」列的就是**当时**登记的名字（有一条断言钉着这份清单）

## Known gaps（本票不做）

- 其余四个策略与 EWMA 延迟样本 → 票 10
- **粘滞键的跨副本共享** → 阶段 13（多副本）。本票是进程内表，多副本下「粘滞」只在单副本内有意义
- 粘滞状态的查询与清除（管理面 / 控制台）→ 阶段 16
- 自定义键**从哪来**（某个请求头、会话 id）本票只定义接口，取值来源随认证（阶段 6）明确
- **「被粘滞的实例被关掉之后换一个」没有端到端断言**：关实例要改配置，而改配置的热重载属阶段 3。
  等价的那一条先落在单元接缝上（候选里不再有那个实例 → 粘滞交给策略重挑并记回）；
  阶段 3 落地后把它补回来，HTTP 那一层的形状是「同一个调用方在实例下线之后仍然有响应，但换了一个实例」

## 实测出来的三件事

1. **探红抓出一条假绿的断言。**「两个调用方各自粘住自己的那一个」最初写成两个调用方**交替**出现，
   而 1:1 权重下轮询在交替来的时候本身也是稳定的 —— 把包装器整体拆掉，它照样绿。
   改成「同一个调用方**连着**来两次」才真的判得出粘滞。
   教训：写粘滞的断言之前先在这个调用序列上确认反例（不粘）真的会换实例。
2. **满容量时的淘汰会连带挤掉「刚命中过的那一个」。** 容量为 2 而三个键轮流入表时，
   第三次插入挤掉的是上一次刚命中的键，不是「更早的那个」—— 访问序 `LinkedHashMap`
   的语义本来如此，写断言时容易想当然。这条最后写成五步序列，每一步都核对了委托计数。
3. **报错里漏了环境变量名。** 第一版的报错只有「不认识的策略名」，没有
   `AIROUTER_ROUTING_STRATEGY`：`SelectionStrategy` 只持有名字清单，说不出这个值是哪个变量给的。
   处置不是让 `select` 去认识配置（那会把依赖方向拆掉），
   而是 `RoutingProperties` 接住一次、补上变量名再抛出去 —— 一层只说该层知道的事。

## 落点

| 文件 | 内容 |
|---|---|
| `select/StickySelector` | 包装器：命中就用，否则委托给被包的那个策略 |
| `select/StickyKeyResolver` | 键从哪来（默认 `callerId`，自定义键优先）—— 本票只有接口与默认实现 |
| `select/SelectionStrategy` | 名字的唯一清单；`of` 对未知名报错并列出登记的名字 |
| `select/SelectionStrategyFactory` | 策略 → 构造器的登记处；漏登记在构造时自检并起不来 |
| `config/RoutingProperties` | `airouter.routing.strategy` / `sticky-enabled` / `sticky-max-entries` 的绑定与校验 |
| `config/UpstreamConfiguration` | 装配：工厂 + 粘滞包装 + 配置校验接进启动期 |
| `routing/StickyKeyMissingException` | 认不出这次调用算谁时的显式失败，由 Face 收口成 400 |
