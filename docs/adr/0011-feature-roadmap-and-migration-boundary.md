# ADR-0011: 能力面补齐的阶段与顺序

- **状态**：已接受（第 2 版，2026-10-25 重写；第 1 版是「功能路线图与迁移边界」）
- **日期**：2026-10-25
- **相关**：[0001 目标态](./0001-project-scope-and-lineage.md)（定义能力面与顺序约束）、[0007 治理模型](./0007-traffic-governance-model.md)、[0012 存储与多副本](./0012-storage-migrations-and-cluster.md)、[0013 配置模型与注册表](./0013-configuration-model-and-runtime-registry.md)

## 背景

[0001](./0001-project-scope-and-lineage.md) 定义了**目标态**（九类能力）与**顺序约束**
（实例维度先于一切作用域类功能；控制台后于管理面 API 契约；Phase C 紧接 Phase B）。

本 ADR 给出落地顺序、依赖与验收要点。**排期本身不是「未来会有人想推翻的决定」，
但顺序是** —— 所以顺序写在 [0001](./0001-project-scope-and-lineage.md) 里锁定，细节留在这里，
调整细节不需要开新的 ADR。

此刻的状态（票 01–09 交付后）：九类能力里只覆盖了「韧性」的一小部分。
**差距的本质不是缺九个模块，而是缺一个维度**：上表里除适配器与记录治理外，
其余六类全部以「服务 → 多个实例」为前提。此刻的实例是配置里的一个地址，
没有标识、没有集合、没有选择过程。

## 决策

### 1. 先建实例维度，再广度铺开

Phase A 全部服务于一件事：让「一个请求进来 → 选中一个实例」这条链真的存在，
且链上每一环都能被单独断言。之后每一类功能都是往这条链上加一节，而不是各自发明一条链。

### 2. 先广度后深度

Phase B 把九类**各铺一层**（每类都能用、都有测试），Phase C 再回头把核心链路做深。
广度先行的理由：九类能力之间存在共享前提（实例维度、作用域标识、结算口径），
先把每类铺一层能尽早暴露「某一类的假设与共享前提不一致」，
而深度优先会让某一类在错误的前提上做得很深。

### Phase A —— 地基：让「选一个实例」这件事存在

| # | 内容 | 依赖 | 验收要点 |
|---|---|---|---|
| A1 | 存储与迁移：H2 默认 / PG 按 `DATABASE_URL`，Flyway 双方言 | — | 两种库都能启动；迁移幂等；**存储缺席时降级并明确记录**（[0012](./0012-storage-migrations-and-cluster.md)） |
| A2 | 配置模型与运行时注册表：服务 / 实例 / 形态 | A1 | 配置完整性校验在**启动期**判红；配置来源可追溯；热重载不重建整个上下文（[0013](./0013-configuration-model-and-runtime-registry.md)） |
| A3 | 实例选择链：`select` 策略 + `routing` 可用性闸门 | A2 | 多实例端到端；选择与健康 / 熔断 / 限流的**顺序被断言**（[0007](./0007-traffic-governance-model.md) 第 3 节） |

> A1–A3 在 `.scratch/p0-foundation/issues/` 里已有对应条目，实施时以那里的验收清单为准。

### Phase B —— 广度：九类各铺一层

| 内容 | 依赖 | 验收要点 |
|---|---|---|
| 负载均衡补齐全策略（含 EWMA 延迟感知） | A3 | 每种策略有确定性断言；EWMA 样本来源可观测；**取消的延迟样本不计入** |
| 规则引擎：条件路由 + 命中统计 | A3 | 首命即止、优先级稳定；命中统计只在决策生效点计数一次 |
| 限流内核：四种算法 + 多级作用域 | A3 | Redis 与本地两级后端；**Redis 不可用降级必测**；拒绝语义进结算 |
| 失败转移：请求级换实例重试 | A3 | 「重试算几次结算」有明确答案并被断言 |
| 响应缓存：确定性请求 + 租户隔离键 | A3 | 流式默认不缓存；租户退化的键规则被钉住 |
| 配额账本：多维多窗口 | A1、限流 | 读不到用量绝不当 0；判定顺序与窗口对齐可断言 |
| 调用历史与记录治理：三档 + AES-256-GCM | A1 | 解密端点仅 ADMIN；密文不含明文回退 |
| 认证与 RBAC：API Key + JWT + 权限矩阵 | — | `X-API-Key` 不透传下游**有测试**；未命中默认拒绝 |
| 可观测性：指标 / 链路 / 慢查询 | 限流、配额 | 告警只出指标与日志；**无任何推送通道**（结构规则判） |
| 多副本：事件广播 / 共享计数 / 分布式锁 | A1、限流、配额 | 单机与多副本两态都测；锁的租约与冷却可断言 |
| 适配器扩展：Anthropic 原生 / Gemini 原生 / 任意兼容厂商声明 | 票 09 | 加一家兼容厂商只改配置；原生形态走端到端 |
| 管理面限流接入同一内核 | 限流 | 不存在第二个限流实现 |

### Phase C —— 深度（紧接 Phase B，不得无限延后）

| 内容 | 依赖 |
|---|---|
| 治理深化：自适应阈值、EWMA 调优、限流维度细化、配额对账 | Phase B 的限流 / 配额 / 负载均衡 |
| 配置版本与回滚深化：差异对比、应用历史版本 | A1、A2 |

### Phase D —— 控制台

| 内容 | 依赖 |
|---|---|
| 管理面 API 契约收口 + 契约测试钉住 | Phase A–C |
| 控制台接入：**适配 legacy 前端**，不重写页面 | 上一条 |

### 3. 本阶段明确不做

- **CI 自动触发**（[0010](./0010-ci-four-gates.md) 记录恢复条件）
- **重写控制台页面**：5.1 万行、92 个 `.vue`，是全项目最贵的资产，重做性价比最低
- **一次性铺满 63 个权限码**：先分类建台账，按需接
- **照搬 legacy 的 6 个 OpenAI 兼容适配器**：约 3.5k 行重复，差异只在默认地址与字段名

### 4. 每个阶段打基线

每开始一个阶段前打一次基线（如 `baseline-pre-11`），给「这一阶段改了什么」留一个可 diff 的起点。
它同时是 [0010](./0010-ci-four-gates.md) 结构 gate 的输入。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 先做限流（跳过实例维度） | 作用域标识不存在，做出来是全局开关 |
| 先内存、后置存储 | 存储接入时要回头改所有写入方；且「Redis 挂了怎么办」这一必测行为被无限期推迟 |
| 深度优先（先把限流做透再做下一类） | 某一类可能在错误前提上做得很深；共享前提的不一致会被推迟暴露 |
| 先做控制台 | 管理面 API 形状未稳，前端会被反复打断 |
| 重写前端 | 最贵且最不该先做的资产 |
| 一次铺满 63 个权限码 | 变成配置搬运 |

## 后果

**正向**

- 每类功能都挂在同一条选择链上，作用域与判定顺序只有一处定义
- 广度阶段结束即可演示「九类都能用」，深度阶段在稳定的前提上做

**风险与对策**

| 风险 | 对策 |
|---|---|
| Phase B 铺得很宽但都不深 | Phase C 必须在 Phase B 结束后**立刻**排期，不是无限延后（这条写在 [0001](./0001-project-scope-and-lineage.md) 的顺序约束里） |
| 结构规则从 9 条扩到十几条，漏写等于静默失效 | 每加一条规则配一个「违规样例会红」的测试 |
| 管理面 API 形状在开发过程中反复改，控制台接入被反复打断 | 契约测试先行（Phase D 的前置条件） |
| 存储进入后测试时间变长 | 按 gate 分组跑（[0008](./0008-verification-and-quality-gates.md) 第 7 节） |

## 如何验证

- [ ] Phase A 出口：`service / instance / shape` 三级存在，多实例端到端打通，选择链顺序有断言
- [ ] Phase B 每一项都有「能用」与「有测试」两条证据，缺一不算完成
- [ ] 依赖缺席路径（Redis / DB）在每一项上都有断言，而不是「测试环境没有就跳过」
- [ ] 每个阶段开始前的基线 tag 存在
- [ ] Phase C 在 Phase B 结束后立刻排期（不被插入其他工作）
