# ADR-0008: 验证策略与质量门禁

- **状态**：已接受（第 2 版，2026-10-25 重写）
- **日期**：2026-10-25
- **相关**：全部其他 ADR —— 它们是本 ADR 要锁住的对象；[0010 CI 暂缓](./0010-ci-four-gates.md)

## 背景

来源项目看起来测试很充分：**426 个测试文件、4,266 个 `@Test`**。但结构决定了这些测试提供不了保护：

| 事实 | 含义 |
|---|---|
| `@SpringBootTest` 只有 **4 个** | 几乎没有真正跑起来的容器；绝大多数测试不经过装配，发现不了装配期问题 |
| 17 个命名带 `IntegrationTest` 的类全部使用 mock | 名字是集成测试，实质是单元测试 |
| 6 个真正需要 Redis / Postgres 的测试被 `@EnabledIfEnvironmentVariable` 关掉，且该变量从未设置 | 它们不会执行，也不报错，只是在报告里显示「通过」 |
| `config/suppressions.xml` 186 行，对 `.*\.java` 抑制了文件长度、命名、`NeedBraces` | checkstyle 对整个代码库事实上不生效 |
| `pom.xml` 的 `dev` / `prod` profile 里 `checkstyle.skip`、`spotbugs.skip`、`jacoco.skip` 全为 `true` | 默认构建路径下所有门禁被关闭 |
| `.github/` 目录不存在 | 没有任何 CI |

结论：**端到端验证能力接近于零。** 这不是测试多不多的问题，而是**测试能否发现「编译通过但行为变了」**
这类变更的问题。而 Jackson 2 → 3 的迁移（[0002](./0002-tech-stack-and-version-pinning.md)）
恰恰主要产出这种静默变更 —— 所以验证策略必须先于迁移落地。

## 决策

### 1. 门禁不允许被跳过，且不允许有抑制文件

**不提供任何 `skip` 开关，不设 `suppressions.xml`。** 一旦存在全局抑制或 profile 级跳过，
门禁就不再是门禁，而变成一个可以随手关掉的提示。

「不许存在」被写成构建断言而不是文档约定：enforcer 的 `requireFilesDontExist` 直接判
`config/checkstyle/suppressions.xml` 与 `config/spotbugs/exclude.xml` 不存在。

两个工具的**分析范围是全部源码，包括测试**。这不是默认如此（两者默认只看 `src/main`）。
代价是结构规则的「故意违规」样例类也要遵守风格规则；收益是不存在「某种代码天生不在门禁范围内的角落」
—— 而这类角落正是抑制文件的雏形。

违约的处置路径是**改代码**；确实无法避免的情形，处置路径是写一份 ADR，不是加一行例外。

### 2. 测试金字塔（按实际用途分层，不按比例凑数）

| 层 | 用途 | 手段 |
|---|---|---|
| **契约测试** | 锁住对外 wire format。最需要的一层，也是来源项目完全没有的 | golden file：一个用例一个目录，放 `upstream.json` + `expected.json` 即被发现，**不需要改任何测试代码** |
| **集成测试** | 锁住跨组件行为：流式终态、治理联动、存储与降级 | 打本机真实依赖（Redis 7 / PG 16）；`StepVerifier` 断言事件流；`@Tag("integration")` |
| **单元测试** | 锁住纯逻辑（限流算法、选择算法、翻译函数） | 无容器、以无 mock 为主 |

关键区别：来源项目的单测大量用 mock 验证「我调用了我以为我要调用的东西」，
这类断言在重构时必然失效却从不报错。这里的单测优先针对**有输入输出的函数**。

### 3. 三条必须能被自动验证的核心契约

| 契约 | 怎么验 | 对应 ADR |
|---|---|---|
| **流式失败必须驱动熔断** | 上游连续流式失败 N 次，断言熔断进入 OPEN。来源项目里这条永远不会通过 | [0006](./0006-streaming-terminal-outcome-contract.md) |
| **CHUNK_PARSE_COUNT = 1** | 计数器断言：一次流式处理中对同一份字节的 JSON 解析次数为 1 | [0005](./0005-canonical-intermediate-representation.md) |
| **新增 provider 不需要改 face** | 新增形态后 `faces` 与 `core` 的改动量为零，用 `git diff` 统计差异 | [0003](./0003-module-structure-and-dependency-direction.md) |

### 4. 流式必须有专门断言

`StepVerifier` 要断言的不只是「有没有数据」：

- 终态事件**恰好出现一次**（正常、异常、超时三条路径各一次）
- 取消路径下 `Terminal` 不出现，且熔断状态不变
- 跨 chunk 边界的内容不会被切坏（UTF-8 多字节字符被切在两个 TCP 段之间）

### 5. 集成依赖打本机真实实例，而不是每轮拉镜像

本机已跑着 **Redis 7（`:6379`）** 与 **PG 16 + pgvector（`:5432`）**。
集成测试直接打它们，不用 Testcontainers：起镜像的时间成本换不来等价的收益，
而真实实例能暴露序列化差异、连接行为与事务语义 —— 这正是 mock 与桩给不出的。

被否决的不是「用容器」而是「用**临时**容器」：[0010](./0010-ci-four-gates.md) 里 CI 恢复时，
流水线一侧用服务容器提供同样的两个端点，测试代码不变。

### 6. 回放上游能控制到字节块一级，不靠 sleep

`RecordedUpstream.replayStream(status, chunks, between)` 可以造出
「一个多字节字符被切在两个 TCP 段之间」「讲完但故意不发 `[DONE]`」这类真实端点给不出的样本。

**时间相关的断言要等条件成立，不要睡固定时长再比数字** —— 内核缓冲区大小这类环境差异
会让本机的数字在 CI 上翻倍。判「停住了」就等它停（`feedFullyWritten()` + 停滞轮询）；
判「有没有把整条流吃进来」就看样本写没写到头。

### 7. 每个测试类必须属于一道 gate

`@Tag("unit" / "integration" / "architecture")` 三选一，标准是**启不启容器、出不出网**。
忘标会让这个类不进入任何一道 gate，而这类遗漏由 `EveryTestBelongsToAGateTest` 判红，不靠人记得。

**不要用 ArchUnit 自带的引擎**（`@AnalyzeClasses` + `@ArchTest`）：它看不见类上的 `@Tag`，
按 gate 筛选时整个类会被静默漏掉（`ModuleStructureTest` 就是这样被漏过一次）。改为普通 `@Test` + `@Tag`。

### 8. 故意制造上游失败的用例必须交代它与熔断的关系

默认阈值是 3，同一个测试类里三条失败就会把熔断打开，于是后面某条用例收到的是
`instance_unavailable` 而不是它想看的上游错误 —— 表现为一条**与执行顺序有关**的偶发红。

- 断言「失败的归类与形状」的类（`FailureAndTimeoutEndToEndTest` 等）把阈值调高并写明理由
- 断言熔断本身的类（`CircuitBreakerEndToEndTest`）在 `@BeforeEach` 里用生产路径把电路恢复到闭合

### 9. 真实端点的测试不做静默跳过

`local` 档位的两条端到端测试打本机模型端点，端点没起来时它们**会红并给出指路信息**，不跳过。
一个可以被跳过的兼容性测试等于没有。

### 10. 没有 jacoco

没有任何故事要求覆盖率下限，在没有生产代码的阶段摆一个阈值只会得到空数字。要加就先补故事。

### 11. CI 暂缓期间的验证以本地为准

用户决定：功能优先，CI 后置（[0010](./0010-ci-four-gates.md)）。
暂缓期间**唯一权威的验证是 `./mvnw clean verify`**（不带任何 skip 参数），
每完成一个阶段打一次基线，给「改了什么」留一个可 diff 的起点。

## 被否决的方案

| 方案 | 否决原因 |
|---|---|
| 保留一个小的 suppressions 文件用于「遗留代码例外」 | 一旦开口子例外就会增长；且本项目是全新构建，`legacy/` 是素材不是生产代码 |
| 先做迁移再补测试 | Jackson 3 的静默变更在没有契约测试时无法识别，等于盲改 |
| 用覆盖率作为主要门禁 | 来源项目证明了高 Mockito 覆盖率与真实验证能力几乎没有相关性 |
| 用 mock 替代真实 Redis / Postgres | mock 出来的依赖不会暴露序列化差异、连接行为、事务语义 |
| 每轮用 Testcontainers 临时起依赖 | 本机已有常驻实例；临时镜像的成本不换来等价收益 |
| 用 `sleep` + 数字比较做时间相关断言 | 环境差异会让数字翻倍；判「停住」要等条件成立 |
| 用 ArchUnit 自带引擎跑结构规则 | 看不见 `@Tag`，按 gate 筛选时被静默漏掉（已踩过一次） |
| 允许测试在依赖缺席时跳过 | 可以被跳过的兼容性测试等于没有 |

## 后果

**正面**

- Jackson 3 迁移期间的每一次行为变更都能被契约测试捕捉
- 依赖方向的破坏在构建期暴露，而不是在生产事故里发现
- `./mvnw clean verify` 一条命令即可获得可判断的结果

**负面**

- 集成测试依赖本机常驻的 Redis / PG / 模型端点：新机器上要先按 runbook 起起来，
  否则集成测试会红（这是刻意行为，但提高了首次上手的门槛）
- golden file 需要人工维护：协议变更时要同步更新，这会带来摩擦（这是刻意的，它强制人审视变更）
- 没有 skip 开关意味着本地临时构建也无法绕开门禁，需要接受稍慢的反馈
- CI 暂缓期间，分支上的「有没有真的跑过测试」只能靠本地纪律（[0010](./0010-ci-four-gates.md) 记录恢复条件）

## 如何验证

- [x] 根 POM 与所有子模块 POM 中不出现任何门禁 skip 配置
- [x] 仓库里不存在 checkstyle / spotbugs 的抑制或排除文件（enforcer 判文件不存在）
- [x] `./mvnw clean verify` 在只有 JDK（无预装 Maven）的机器上可直接运行
- [x] 每个测试类都有允许集合内的 `@Tag`（`EveryTestBelongsToAGateTest`，且该守门自身会反向验证）
- [x] 破坏任意一条核心契约（例如让某个组件绕过 `OutcomeObserver`）会导致构建失败
- [x] 契约测试一个用例一个目录，加用例不需要改测试代码
- [ ] 集成测试打真实 Redis / PG，且**依赖缺席时的降级路径有断言**（Phase A）
- [ ] CI 恢复后四个 gate 全部为 required status check（[0010](./0010-ci-four-gates.md)）
