# ADR-0016：可观测性（指标 / 链路 / 慢查询 / 错误追踪 / 安全告警）

- 状态：已接受
- 日期：2026-10-26
- 相关：[0005](./0005-streaming-terminal-outcome-contract.md)（唯一数据源是 Outcome）、[0001](./0001-scope-target-state-and-sequence.md) 第 4 节

能力面：**第 7 类（可观测性）**

## 1. legacy 的事实（已核实）

`monitor/tracing` 相关路径下 **91 个自研 Java 类**（实测 `find monitor/tracing -name '*.java'`）：自研 span、自研 tracer、自研 LRUCache、
自研 `SpanCache` / `CachedTraceData`。另有 `monitor/monitoring/`、`monitor/controller/QuotaMonitoringController` 等。

**这是 legacy 最贵的一处自建**：一套与 OpenTelemetry 平行的追踪体系，需要自己维护传播、采样、导出、存储。

## 2. 决定

**(a) 用 OpenTelemetry，不自研追踪。**
91 个自研类**不搬**。span 覆盖：请求入口 → 选择 → 出网 → 终态。

**(b) 指标用 Micrometer + Prometheus registry。**
核心维度：服务、实例、形态、租户、成败。三类指标：计数、直方图（延迟与 token）、仪表（在途、熔断状态）。

**(c) 慢查询分析**：超过阈值的调用**按实例聚合成指标 + 一条结构化日志**，**不落库**。
> 慢是**实例**的属性，不是请求的属性。按请求记录的慢查询看不出「是哪台慢」。
> 落库会让慢查询变成第二套调用历史（[0015](./0015-call-history-and-record-governance.md)），
> 而「哪台慢」这个问题，一个按实例打标的直方图就能回答。

**(d) 错误追踪**：按错误类型聚合成异常事件（首次/最近出现时间 + 样本），**同样只进指标与日志，不落库**。
与指标的差别：指标回答「多少」，错误追踪回答「哪些」。
> 「哪些」由日志平台聚合回答，不需要我们再存一份 —— 存了就是第二套记录治理。

**(e) 安全告警**：针对异常模式（凭据失效暴增、越权尝试、单租户突增）。

**(f) 告警出口被有意限定为 Prometheus 指标 + 结构化日志。**
**仓内不实现任何推送通道**（邮件 / Webhook / IM）。请在 Alertmanager 或日志平台里接。
> 这是一条**非目标**，不是「还没做」。理由：推送通道的运维（退避、去重、凭据、送达确认）
> 是一个独立产品的体量，而 Alertmanager 与日志平台已经解决。

**(g) 告警冷却**：同一告警在冷却期内不重复触发。
**多副本下冷却状态必须共享（Redis）**，否则 N 个副本会各发一次。

## 3. 数据源纪律

所有观测数据**只从 `OutcomeObserver` 取**（[0005](./0005-streaming-terminal-outcome-contract.md)）。
组件不得各自埋点、不得自己判定成败 —— legacy 的适配器里内嵌指标与 tracing 调用，
正是「流式绕过治理」的成因之一。

例外只有两类，且都不涉及成败判定：
- transport 层的字节级计数（在途连接、缓冲区）
- 选择链各步的耗时（用于定位慢在哪一步）

## 4. 裁决

| legacy 的东西 | 裁决 |
|---|---|
| 91 个自研 tracing 类 | **不搬** |
| `LRUCache` / `SpanCache` | **不搬**（Caffeine 或不需要） |
| Prometheus 指标定义与命名 | **改**（维度加实例与形态；命名统一前缀） |
| 慢查询、错误追踪、安全告警的思路 | **搬**（改：数据来自 Outcome，不用自研 tracing） |
| 告警冷却 | **搬**（改：多副本下共享到 Redis） |

## 5. 验收

- 流式与非流式的指标口径一致（都算到终态）—— 一条断言覆盖两类路径
- 取消被单独计数，且**不计入**失败率（否则移动端关页面会把失败率打满）
- 慢查询能按实例聚合出「哪台慢」
- 告警冷却在多副本下只触发一次（有断言：两个副本共享冷却状态）
- 仓内不存在任何邮件 / Webhook / IM 推送实现（结构规则可加一条）
