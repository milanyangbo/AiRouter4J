## Problem Statement

仓库现在**没有任何可构建的东西**。五个 `pom.xml`（含根 pom）与四个模块的 `src/` 已在阶段 0 删除
（`10c42a1` + `eedaff6`），被删掉的是主代码 4,733 行、测试 5,471 行、23 个契约资源文件
（其中 8 个是从真实 Ollama 抓的响应样本）。

从这个状态出发有三件具体的事卡住了：

1. **什么都无法验证。** 九类能力面的设计与 16 阶段的排期都写完了，但没有一行代码能被编译、
   没有一个测试能被运行。后面每一个阶段的验收标准都依赖「先有一个能跑的构建」。
2. **上一轮最贵的两样东西只以文档形式存在。** 它们不是设计，是**被证明过的资产**：
   - **契约测试的 golden 样本** —— 未来任何框架升级唯一能告诉你「序列化行为变了」的东西；
   - **流式终态与结算的纪律** —— legacy 最贵的缺陷（流式路径绕过治理，半截响应被记成 100% 成功）的反面。
   重建时最容易犯的错是：把骨架重搭一遍，却把这两样当成「阶段 7 再说」的东西往后推。
3. **守门机制没有载体。** 九条结构规则（R1–R9）随 `StructuralRules` 一起删了。
   它们是「依赖方向被违反时构建变红」的执行者；缺了它们，「core 不许依赖框架」就只是一句话。

用户要的是：**一条真实请求穿过网关拿到响应，并且这条请求的成败被判对** ——
尤其是流式那条路：上游不讲完就不是成功。

---

## Solution

分三段，每段结束都是可验证的状态，不攒到最后：

**阶段 0 —— 构建骨架。** 按 ADR-0002 §4 与 ADR-0003 §3 重建五个 `pom.xml`，
装上 enforcer / checkstyle / spotbugs / surefire 分组，并按 ADR-0003 的 **R1–R9 编号表复原九条结构规则**
（编号不重排）外加两道守门测试。本阶段的验收不是「构建绿」，是**「故意违反一条规则就红」**。

**阶段 1 —— core 领域模型与端口。** Canonical 六型事件、两个端口、`GatewayError`、`Outcome`，
依赖树里出现任何框架即构建失败。同时立起契约测试的发现机制与目录骨架。

**阶段 2 —— 打通一条请求。** `openai` 形态一个 Provider + 一个 Face + SSE 传输 + 流式终态与结算。
从 HTTP 入口进，到一个**可录制的上游**出 —— 这个上游能控制到字节块一级，
于是「一个多字节字符被切在两个 TCP 段之间」「讲完但故意不发 `[DONE]`」这类
真实端点给不出、却又必须被确定性断言的样本，都由它制造。

三段结束时：非流式与流式各有一条真实请求穿过网关；上游不发结束哨兵 → `Failed` 而不是 `SUCCESS`；
客户端断连 → `CLIENT_CANCELLED` 且无事件；一条流恰好结算一次。

## User Stories

### 构建骨架

1. 作为**网关开发者**，我想要 `./mvnw clean verify` 能从头跑到尾且不带任何 skip 参数，这样默认路径就包含了全部门禁，不需要人记得加参数
2. 作为**网关开发者**，我想要根 pom 与四个模块 pom 存在，这样四个模块才能被编译
3. 作为**网关开发者**，我想要 Maven Wrapper 入库，这样只有 JDK 的机器也能构建
4. 作为**网关开发者**，我想要 enforcer 卡住 JDK 版本、重复上界依赖、插件版本与依赖收敛，这样版本漂移在构建期就红而不是运行期才现形
5. 作为**网关开发者**，我想要 enforcer 的抑制文件被禁止，这样「先加个例外回头再改」就没有入口
6. 作为**网关开发者**，我想要 checkstyle 与 spotbugs 的作用域包含测试源码，这样测试代码不会成为静态分析的法外之地
7. 作为**网关开发者**，我想要 surefire 按 gate 分组，这样 `unit` / `integration` / `architecture` 能被分别运行
8. 作为**代码审阅者**，我想要九条结构规则按 R1–R9 的原编号复原，这样既有 ADR 与 AGENTS.md 里对 R4 / R9 的引用不会失效
9. 作为**代码审阅者**，我想要每条规则旁边写清它保护什么，这样有人想加例外时得先回答「保护的东西不要了？」
10. 作为**代码审阅者**，我想要有一条测试断言「规则真的会红」，这样规则不会因为没人试过而悄悄失效
11. 作为**代码审阅者**，我想要每一个测试类都必须标 `@Tag`，漏标即红，这样不会有测试悄悄落进「不进任何一道 gate」的空隙
12. 作为**后续能力面开发者**，我想要「空包不要提前开」被断言，这样结构规则不会看起来已覆盖一块实际不存在的区域
13. 作为**后续能力面开发者**，我想要 `package-info.java` 是强制的，这样每个包知道什么、不该知道什么有地方可读

### 领域模型与端口

14. 作为**网关开发者**，我想要 `core` 的依赖树里出现 Spring / Jackson / Reactor 即构建失败，这样领域模型不会被框架形状污染
15. 作为**网关开发者**，我想要端口返回 JDK 类型（`CompletionStage` 与 `Flow.Publisher`）而不是 Reactor 类型，这样 `core` 不必依赖 Reactor
16. 作为**网关开发者**，我想要 `CanonicalStreamEvent` 是 sealed 且实现层六型，这样「概念四态、实现六型」的差别有地方表述
17. 作为**网关开发者**，我想要 `Ping` 是显式类型，这样「保活帧不是内容、也不是终态」在类型上可见
18. 作为**网关开发者**，我想要 `ToolCallDelta` 暂不引入，这样不会先画一个未被样本钉住的类型
19. 作为**网关开发者**，我想要 Passthrough 存 JSON 原文而不是解析后的对象，这样厂商在响应任意层挂的私有字段都能被转发
20. 作为**网关开发者**，我想要 `GatewayError` 是错误形态的唯一收敛点，这样从传输故障到上游 4xx/5xx 最终只有一种形状
21. 作为**网关开发者**，我想要 `UpstreamFailure` 是 unchecked 且只有 Face 在边界上收口一次，这样中间层不会各自吞掉它
22. 作为**网关开发者**，我想要 `Outcome` 带 `requestId` / `serviceId` / `instanceId` / `OutcomeKind` / `latency` / `usage`，这样后续能力面的维度有来源
23. 作为**后续能力面开发者**，我想要 `OutcomeKind` 互斥且穷尽（成功 / 上游失败 / 上游超时 / 客户端取消），这样新增一种结局必须先改这个枚举
24. 作为**网关开发者**，我想要只有 Provider 能构造 `Outcome`，这样「谁能判定成败」只有一个答案

### 端到端：非流式

25. 作为**调用方**，我想要用标准 OpenAI 客户端向网关发一次非流式请求并拿到响应，这样我不必为这个网关改写客户端
26. 作为**调用方**，我想要响应能被标准客户端解析，这样翻译层的输出是协议正确的而不只是「看起来对」
27. 作为**网关开发者**，我想要非流式与流式走同一条路径，这样流式不会绕过治理
28. 作为**调用方**，我想要上游返回 4xx/5xx 时收到对应的错误，这样失败不会变成成功的空响应
29. 作为**网关开发者**，我想要上游地址不可达时收到 `UPSTREAM_FAILURE`，这样网络故障与上游拒绝有区分

### 端到端：流式

30. 作为**调用方**，我想要以 SSE 收到流式响应，这样我能逐块拿到内容
31. 作为**调用方**，我想要收到 `[DONE]` 哨兵，这样我知道流结束了
32. 作为**网关开发者**，我想要终态由 Provider **显式**发出，这样成败不依赖 `onComplete` / `onError` 的隐式推断
33. 作为**网关开发者**，我想要终态是这条流的**最后一个**事件，这样终态之后的帧不会泄漏到客户端
34. 作为**网关开发者**，我想要上游收了连接但没发结束哨兵时补发 `Failed(upstream_closed)`，这样半截响应不会被记成成功
35. 作为**网关开发者**，我想要帧间静默超过 `idleTimeout` 时判定 `UPSTREAM_TIMEOUT`，这样沉默的上游不会占着连接
36. 作为**网关开发者**，我想要 `idleTimeout` 是**块间**时长而不是总时长，这样一条想很久的流不会被误杀
37. 作为**网关开发者**，我想要对 `text/event-stream` 的下游响应不设 `ResponseTimeout`，否则长流会被基础设施掐断
38. 作为**网关开发者**，我想要 SSE 的 SLO 三角（idleTimeout × 最大累积内容 × 缓冲区）三者都显式配置，这样它有明确边界
39. 作为**调用方**，我想要中途断开时上游连接被释放，这样取消不会泄漏资源
40. 作为**网关开发者**，我想要取消**不产生事件**但**仍然结算**成 `CLIENT_CANCELLED`，这样接收方不在时不会往断开的下游发东西，同时熔断不会被取消误导
41. 作为**网关开发者**，我想要一条流**恰好结算一次**，这样不会重复扣配额、不会重复写调用历史
42. 作为**网关开发者**，我想要 `latency` 一律算到收到终态为止，这样流式与非流式的延迟可比
43. 作为**网关开发者**，我想要 `usage` 优先取上游回报，取不到时才讨论本地估算
44. 作为**网关开发者**，我想要累积内容有上限且超限截断，这样一条失控的流不会吃满内存
45. 作为**网关开发者**，我想要截断只影响展示、不影响计费，这样 token 估算走独立的字符计数轨道

### 字节层

46. 作为**网关开发者**，我想要一个多字节字符被切在两个 TCP 段之间时仍能正确合并，这样中文响应不会在块边界乱码
47. 作为**网关开发者**，我想要空 `data:` 帧被忽略而不是被当成内容，这样上游保活不会污染输出
48. 作为**网关开发者**，我想要 `CHUNK_PARSE_COUNT` 恒为 1，这样同一个块不会被解析两次
49. 作为**网关开发者**，我想要任意分块方式下合并结果唯一，这样分帧器不依赖上游的分块习惯
50. 作为**网关开发者**，我想要上游保活注释（`Ping`）不影响终态判断，这样保活不会冒充内容或结局

### 形态与配置

51. 作为**网关开发者**，我想要端点地址形态由**形态**自己决定（OpenAI 兼容以 `/v1` 结尾），这样「少了后缀变成运行期 404」不会发生在启动之后
52. 作为**网关开发者**，我想要地址形态是**启动期校验**而不是约定，这样配错了起不来而不是等到调用才 404
53. 作为**网关开发者**，我想要形态在配置里显式给出、不允许按地址猜，这样同一台本机 Ollama 上 `/v1` 与 `/api` 两种地址都能被正确区分
54. 作为**网关开发者**，我想要凭证只在形态需要它时才必填，这样本机 `local` 档位不必造一把假密钥
55. 作为**网关开发者**，我想要形态差异只留在 codec 的「一帧字节 → 哪些事件」，这样分帧之后的逻辑与形态无关
56. 作为**后续能力面开发者**，我想要新增形态时不触碰 `faces` 与 `core`，这样抽象没长错位置
57. 作为**网关开发者**，我想要 `local` 档位在无网络环境下也能起来并完成一次受支持的调用，这样验证能从「凭印象」挪到「对着真实字节」
58. 作为**网关开发者**，我想要档位切换只改 profile 或环境变量、不改代码，这样它是一条部署开关而不是代码分支
59. 作为**安全审阅者**，我想要 baseUrl 与凭证只从环境变量读取，配置文件里只能是占位符
60. 作为**安全审阅者**，我想要有一条测试断言受跟踪文件里不含真实凭证，这样凭证泄露在构建期就红
61. 作为**网关开发者**，我想要本机地址一律写 `127.0.0.1` 不写 `localhost`，这样不会踩到 IPv6 解析差异

### 契约测试与升级安全网

62. 作为**维护者**，我想要契约测试用真实上游样本做快照比对，这样框架升级时最先红的是它们
63. 作为**维护者**，我想要契约测试锁定 wire format 的完整行为含边界情形，这样序列化行为的细微变化无所遁形
64. 作为**网关开发者**，我想要一个用例一个目录、放入样本文件即被发现，**不需要改测试代码**，这样加样本不需要懂测试框架
65. 作为**后续能力面开发者**，我想要契约测试目录骨架在本阶段就位，这样阶段 2 打通时只需放样本
66. 作为**维护者**，我想要历史上抓过的样本能从 tag `baseline-pre-11` 取回，这样真实字节不会因为代码被删而丢失
67. 作为**维护者**，我想要非流式比响应 JSON、流式比**帧序列**（含 `[DONE]` 哨兵本身），这样哨兵的存废是一个被断言的事实

### 可验证性

68. 作为**网关开发者**，我想要上游是一个能控制到字节块一级的录制器，这样真实端点给不出的样本能被确定性制造
69. 作为**网关开发者**，我想要录制器能制造「讲完但故意不发结束哨兵」，这样最容易被写成成功的那条路径有测试守着
70. 作为**网关开发者**，我想要录制器能制造块间静默，这样 `idleTimeout` 不必等真实网络卡一次才能验证
71. 作为**网关开发者**，我想要录制器能报告它收到几次请求与写出多少块，这样「没有出网」是一个可断言的数
72. 作为**网关开发者**，我想要时间相关的断言等条件成立而不是睡固定时长再比数字，这样本机的数字换个环境不会翻倍
73. 作为**网关开发者**，我想要背压向两端传导，这样网关不会在中间堆积
74. 作为**后续能力面开发者**，我想要本阶段留下的接缝是**最高**的那一层（HTTP 入口），这样后续能力面不必另开接缝

## Implementation Decisions

### 模块与依赖方向

- 四个模块按 ADR-0003 §1：`core` / `gateway` / `agent` / `app`，**不按技术角色分包**。
  阶段 0–2 期间 `agent` 只有壳，不引入 Spring AI 依赖（ADR-0007 属阶段 14）
- 包按阶段 0–2 的实际内容开：`config` / `faces` / `providers` / `transport` / `observe`。
  `registry` / `select` / `store` / `cluster` / `admin` **不在本阶段开** —— 空包会让结构规则看起来覆盖了一块不存在的区域
- 结构规则按 ADR-0003 §3 的 **R1–R9 编号表复原，编号不重排**。`R1` 由 Maven enforcer 判红（`core` 依赖树无框架），
  其余由 ArchUnit 库判红，但**不用 ArchUnit 的 `@AnalyzeClasses` 引擎**（它看不见类上的 `@Tag`，
  按 gate 筛选时整个类会被静默漏掉）—— 改用普通 `@Test` + `@Tag`
- 两道守门：`GuardsActuallyFireTest`（规则真的会红）、`EveryTestBelongsToAGateTest`（每个测试类都标了允许的 gate）

### 领域模型

- 端口返回 JDK 类型：`CompletionStage<CanonicalResponse>` 与 `Flow.Publisher<CanonicalStreamEvent>`，
  两侧各用一次 `JdkFlowAdapter` 接上 Reactor
- `CanonicalStreamEvent` 是 sealed，实现层六型（`Opening` / `TextDelta` / `Usage` / `Ping` / `Terminal` / `Failed`）。
  `ToolCallDelta` **不引入**
- Passthrough 是 `Map<String, String>`，值是 JSON 原文，挂在响应顶层、每个候选、每条消息与 usage 内部
- `Outcome` 由 **Provider 构造**，其它包不得构造

### 流式终态与结算

- `Terminal` / `Failed` 是终态的**唯一**形态，由 Provider **显式**发出；终态是最后一个事件
- `OutcomeObserver` 是结算的**唯一**收口点。阶段 2 只把它接到一个**可观测的结算记录**上
  （后续能力面从这里取结果）；熔断器本体属阶段 7，接入的是同一个点
- `StreamState.claim()` 保证一条流恰好结算一次
- 终态来源矩阵按 ADR-0005 §3，四条易错点按该节正文
- 本阶段结算记录必须能区分四种 `OutcomeKind`，使「取消不会冒充失败」可被断言

### 形态

- 阶段 2 只落地 **`openai` 一种形态**，SSE 一种分帧。`ollama` 形态与其逐行 JSON（NDJSON）分帧**不在本阶段**
  （见 Further Notes 里的排期缺口）
- 形态自述三件事：地址形状、要不要凭证、流怎么结束（经由各自的分帧器）
- 地址形态是**启动期校验**：`openai` 形态的端点必须以 `/v1` 结尾且不带尾斜杠。
  Spring AI 2.x 不再自动补这个后缀，少了它不在启动期报错、只会变成运行期的 404
- 措辞（错误文案与「什么算异常结束」的解释）由形态自己提供，不写在共享的错误映射里 ——
  历史上为了改一处文案动了共享映射，结果另一个形态的 golden 基线一起变红

### 配置与凭据

- baseUrl / 凭证 / 超时 / 档位一律走环境变量，变量名清单以 `.env.example` 为准
- 凭证只在形态需要它时才必填（`openai` 形态需要）
- `local` 档位指向本机 `127.0.0.1:11434/v1`，三个端点变量都可以不设

### 契约测试

- 三个目录的发现机制在阶段 1 立起：一个用例一个目录，放 `upstream.json` + `expected.json` 即被发现

## Testing Decisions

### 好测试的标准

- **只测外部行为，不测实现细节**：能单独回答「这条业务流程走通了吗」的是好测试；
  需要知道内部有几个类、调用过几次才能读懂的不是
- **换一种等价实现不用改**：如果重写内部实现会让它变红，它测的是实现
- **入口选在责任的边界上，不在系统的边界上**：本阶段的边界是 HTTP 入口
- 组织界限（`docs/agents/testing.md` 的硬约束）：每模块测试文件 **≤10 个（最多 20）**、每文件方法 **≤20 个**、行覆盖率 **≥60%**

### 测试文件预算（本阶段必须落在上一条界限内）

`airouter-app` 是本阶段测试的主体，规划如下 —— 超了就要合并，不允许一功能一文件地铺开：

| 用途 | 文件 |
|---|---|
| 结构与守门 | 结构规则守门（含 `EveryTestBelongsToAGate`）、规则真的会红、空包不被规则覆盖 |
| 契约 | 非流式 golden、流式 golden |
| 端到端 | 非流式、流式、取消、失败与超时、恰好结算一次、标准客户端解析、翻译层不变量 |
| 配置与启动 | `local` 档位能起来、启动期校验、凭证未入库 |

`gateway` 与 `core` 各自不超过 10 个。

### 接缝

- **接缝是 HTTP 入口**（可用的最高层）：请求从 HTTP 进，打到录制上游，断言在 HTTP 出口
- **上游是录制器，不是真 Ollama**：阶段 2 的端到端用一个能控制到字节块一级的录制上游。
  它的能力至少包含：以指定状态码回放整段响应、以 SSE 回放、以**字节块列表加块间间隔**回放、
  保持连接打开并静默一段时间、报告收到的请求次数与写出的块数、记录最后收到的请求体与路径
- 真 Ollama 的用途是**抓样本**（`docs/runbook/local-openai-endpoint.md` 记录了方式），
  **不进常规测试**：真实服务在跑的假设会让终态类断言失去确定性
- 这直接支持本阶段最要紧的两条断言：**「讲完但故意不发结束哨兵」**与**「一个多字节字符被切在两个 TCP 段之间」**——
  两者都是真实端点给不出、却必须被确定性覆盖的样本

### 三道 gate

- 每个测试类用 `@Tag` 标 `unit` / `integration` / `architecture`，标准是启不启容器、出不出网
- 走 HTTP 入口的端到端归 `integration`
- 集成依赖用**本机真实服务**（PG `:5432` 已确认在跑；Ollama `127.0.0.1:11434` 已确认在跑），**不用 Testcontainers**

### 几条具体到会踩的

- **时间相关的断言等条件成立，不睡固定时长再比数字**。取消与背压的判别用「写出完毕 + 停滞轮询」，
  不依赖固定 sleep
- **故意制造上游失败的用例必须交代它与熔断阈值的关系**：同一测试类里三条失败就会把熔断器打开，
  后面用例收到的是 `instance_unavailable` 而不是它想看的上游错误 —— 表现为一条**与执行顺序有关**的偶发红
- 每个新包（含测试里的样例包）都要补 `package-info.java`，两个静态分析的作用域都包含测试源码
- 本机地址写 `127.0.0.1` 不写 `localhost`

### Prior art

上一轮（tag `baseline-pre-11`）留下的测试形状可复用作本阶段的先例，包括：
结构规则与守门类、契约 golden 类、非流式/流式/取消/失败与超时等端到端类、
标准客户端解析类、恰好结算一次类、`local` 档位启动类、启动期校验类、凭证未入库类。
它们证明这套形状是跑通过的；本阶段按测试文件预算合并同类项，不按原样逐个复活。

## Out of Scope

以下内容**明确不在本阶段**，且不应以「顺便」的名义带进来：

- **注册表、选择链与多实例**：属阶段 3 / 4。本阶段是一个服务、一个实例、一条直通路径
- **熔断器本体**：状态机、冷却、半开探测属阶段 7。本阶段只立结算点与结算记录
- **失败转移**：需要「另一个实例」，属阶段 7
- **规则引擎、限流、配额、响应缓存**：属阶段 8 / 7 / 9 / 7
- **持久化与 MyBatis**：属阶段 5。本阶段**不引入任何存储依赖**
- **认证、API Key 与租户**：属阶段 6
- **可观测性全套**（指标 / 链路 / 慢查询 / 告警）：属阶段 11
- **`ollama` / `anthropic` / `gemini` 形态与逐行 JSON 分帧**：不在本阶段
- **适配器声明（声明式厂商）**：属阶段 12
- **Agent 层**：属阶段 14，本阶段 `airouter-agent` 不引入 Spring AI
- **控制台**：属阶段 16，最后做
- **CI**：暂缓（ADR-0008 §6 的四条恢复条件未满足）。本阶段以 `./mvnw clean verify` 与本地冒烟为准

## Further Notes

### 两处 ADR 与排期之间的缺口（写本 spec 时发现，需回写 ADR-0020）

**(a) `ollama` 原生形态在 ADR-0020 里没有承载点。**
ADR-0006 §1 把 `ollama` 列为四种形态之一，§3 要求「用 SSE 的读法读逐行 JSON，一条事件都产不出来」
必须有断言 —— 但 ADR-0020 的阶段 12 只写了 `anthropic` / `gemini` 原生与声明式厂商。
结果是：逐行 JSON 分帧与它唯一能被证伪的那条断言无处安放。
**建议**：阶段 12 补上 `ollama` 原生形态。

**(b) ADR-0005 §6 的两条验收依赖本阶段之后的组件。**

| 该节的验收 | 所需组件 | 归属 |
|---|---|---|
| 取消 → 熔断器计数不变 | 熔断器本体 | 阶段 7 |
| 本地拒绝 → 无出网、无结算 | 注册表与可用性闸门 | 阶段 3 |

本阶段的等价交付是：**结算记录能区分四种 `OutcomeKind`**，于是「取消被记成 `CLIENT_CANCELLED` 而不是失败」
在这里就成立；熔断器本体接进同一个 `OutcomeObserver` 时，该条自动成立。
「本地拒绝不出网、不结算」推迟到阶段 3（那时才有可用性与未登记的概念）。

### 关于 legacy 代码

`legacy/` 是设计素材库。本阶段涉及的三块（SSE 分帧、终态判定、`local` 档位端点）
逐项按 ADR-0001 裁决（搬 / 改 / 新增 / 不搬），搬进来的必须过三道关：换坐标、适配新契约、
**补它原本没有的失败与缺席路径测试**。已知不搬的包括 91 个自研 tracing 类与 `HttpConfigPushService`。
