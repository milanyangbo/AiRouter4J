# ADR-0008：验证与质量门禁

- 状态：已接受
- 日期：2026-10-26
- 相关：`docs/agents/testing.md`（测试判据，本文件的上位规则）、[0002](./0002-tech-stack-and-version-pinning.md) 第 4 节（pom 需重建）

## 1. 测试怎么写：以功能为单位

规则在 **`docs/agents/testing.md`**，这里只列出与网关强相关的几条硬约束：

- **一个功能一份测试，不是一类一份**。能不能单独回答「这条业务流程走通了吗」是切分标准
- 组织界限：每模块测试文件 **≤10 个**（最多 20）、每文件方法 **≤20 个**、行覆盖率 **≥60%**
- 四条判据：① 坏了会不会立刻有人知道（只写「照样跑、只是结果不对」的）；② 测的是机制契约、自身功能、模型可用性还是装配；③ 换一种等价实现这条测试要不要改；④ 它穿过了多少核心逻辑
- 入口选在**责任的边界**上，不在系统的边界上；接口级契约归验收

## 2. 三道 gate

每个测试类必须用 `@Tag` 标出自己属于哪一道，**标准是启不启容器、出不出网**：

| gate | 内容 |
|---|---|
| `unit` | 纯内存，无容器无网络。策略、codec、规则匹配、结算 |
| `integration` | 起真实依赖（本机 Redis 7 `:6379`、PG 16 `:5432`、Ollama `127.0.0.1`），或走 HTTP 入口的端到端 |
| `architecture` | 结构规则（依赖方向、包边界、规则真的会红） |

忘标会让这个类不进入任何一道 gate，而这类遗漏由 `EveryTestBelongsToAGateTest` 判红，不靠人记得。

**集成依赖用本机真实服务，不用 Testcontainers。** 本机常驻 Redis 与 PG，起容器的收益是「干净」，
代价是慢和一个新的失败模式。需要隔离时用库名/键前缀隔离。

> **不要用 ArchUnit 自带的 `@AnalyzeClasses` 引擎**：它看不见类上的 `@Tag`，
> 按 gate 筛选时整个类会被静默漏掉。改用普通 `@Test` + `@Tag`。

## 3. 契约测试（golden-file）

在 `airouter-app/src/test/resources/` 下三个目录，一个用例一个目录，
放 `upstream.json` + `expected.json` 即被发现，**不需要改任何测试代码**：

| 目录 | 形态 | 比什么 |
|---|---|---|
| `contract/` | OpenAI 兼容，非流式 | 响应 JSON |
| `contract-stream/` | OpenAI 兼容，SSE | **帧序列**，含 `[DONE]` 哨兵本身 |
| `contract-ollama/` | Ollama 原生 | 流式用 `ndjson`（靠末帧 `done:true`），非流式用 `body` |

**它们是未来任何框架升级的唯一安全网** —— 序列化行为变了，最先红的是它们。
样本优先取真实端点（抓取方式见 `docs/runbook/local-openai-endpoint.md`），
历史上抓过的样本可从 tag `baseline-pre-11` 取回。

## 4. 依赖缺席是契约，不是兜底

每一处新依赖都要有一条「它不在」的测试：DB 不在、Redis 不在时，
行为必须是**被断言过**的那一种（降级到哪一档、拒绝还是放行），而不是 NPE 之后被某个 `catch` 吞掉。

## 5. 几条具体到会踩的约束

- **时间相关的断言要等条件成立，不要睡固定时长再比数字**。内核缓冲区大小这类环境差异会让本机的数字在别处翻倍
- **故意制造上游失败的用例必须交代它与熔断阈值的关系**：默认是 3，同一个测试类里三条失败就会把熔断器打开，
  于是后面某条用例收到的是 `instance_unavailable` 而不是它想看的上游错误 —— 表现为一条**与执行顺序有关**的偶发红
- **回放上游要能控制到字节块一级**（`RecordedUpstream.replayStream(status, chunks, between)`）：
  可以造出「一个多字节字符被切在两个 TCP 段之间」「讲完但故意不发 `[DONE]`」这类真实端点给不出的样本
- 每个新包（含测试里的样例包）都要补 `package-info.java` —— 两个静态分析的作用域都包含测试源码
- 本机地址写 `127.0.0.1` 不写 `localhost`

> 上面这几条在 `AGENTS.md` 里也有一份（那是执行侧清单）。**改任何一条都要两处同步**，
> 两处冲突时以本文件为准 —— ADR 存理由，AGENTS.md 存执行。

## 6. CI

**CI 暂缓**（已两次确认：先以功能与本地测试为主）。`.github/workflows/` 已被删除。

恢复自动触发前必须同时满足：

1. 本地 `./mvnw clean verify` 稳定全绿，且「跑了 0 个测试却绿」有两种独立判据（surefire 计数 + 报告解析）
2. 集成 gate 所需的 Redis / PG 在流水线上有确定来源
3. 真实端点的用例有明确处理（不做静默跳过 —— 一个可以被跳过的兼容性测试等于没有）
4. 有 `fetch-depth: 0`：依赖基线 tag 的差异类测试在浅克隆下拿不到基线

## 7. 违约处置

处置路径是**改代码**。确实无法避免的，处置路径是**写一份 ADR** ——
不是加一行抑制、一个排除块或一处 include 例外。
