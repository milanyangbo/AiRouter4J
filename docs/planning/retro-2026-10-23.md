# Retro：2026-10-23 目标对齐

> 这份文件记录**为什么存在这些 ADR**，以及本轮纠偏前后的差别。
> 它是对齐过程的产物，不是设计交付物；稳定结论一律沉淀到 `docs/adr/`。

## 触发

中途一次纠偏：我犯的问题是**把"证明设计能力"放在了"做出能跑的东西"前面**，
并且把大量篇幅写成了"这条在某某场合怎么讲"。目标被替换成了表演目标。

## 纠偏前 → 纠偏后

| 维度 | 纠偏前（错） | 纠偏后（当前共识） |
|---|---|---|
| 项目性质 | 反复强调"从零重写"、不断论证重写的正当性 | **对现有开源网关做二次开发**。这本就是常见兑现方式，不需要辩护 |
| 重构语义 | 追求功能对等 / 逐.Entity.<reiben | **看完原项目后综合取舍**：好的直接拿来、坏的改掉、该增的增、该砍的砍。"重写"指覆盖范围，不是逐 Aliquote ribbon |
| 设计评价口径 | 用"外部评审会不会认可"当主要理由 | **理由回到系统本身**：延迟、正确性、可维护性、故障是否可观测 |
| 分层与架构 | 14 个 Maven 模块的六边形架构、一次性重画全部抽象 | **同样按取舍逻辑处理**：保留有效分层，改掉成环的地方，不为了好看新增层次 |
| 交付节奏 | 一边建筑设计一边写实现代码 | **ADR → spec → tickets**，.ticket 驱动的集成电路 implementation 才动手 |

## 本轮实测到的事实（ADR 的输入，均为实测而非记忆）

构建可用性（`repo1.maven.org` 逐个探测）：

| 坐标 | 结果 |
|---|---|
| `spring-boot-starter-parent:4.1.2` | HTTP 200 |
| `spring-ai-bom:2.0.1` | HTTP 200 |
| `spring-ai-starter-model-openai:2.0.1` | HTTP 200 |
| `spring-ai-agent-utils:0.13.0` | HTTP 200 |
| `spring-ai-session-bom:0.10.0` | HTTP 200 |
| `maven-checkstyle-plugin:3.6.0` | HTTP 200 |
| `checkstyle:10.21.2` | HTTP 200 |
| `spotbugs-maven-plugin:4.8.6.6` | HTTP 200 |
| `spotbugs-maven-plugin:4.9.3` | **HTTP 404（不存在）** |

关键硬约束 —— 直接拉下 `spring-ai-starter-model-openai-2.0.1.pom` 读到的依赖：

```
spring-boot-starter-webclient   : 4.1.1
spring-boot-starter-restclient  : 4.1.1
```

**结论：Spring AI 2.0.1 与 Spring Boot 4.1.x 是绑定的，不是"建议搭配"。**
因此不存在"网关留在 Boot 3.5、只把 Spring AI 引进来"这条中间路线 ——
选了 Spring AI 2.x 就等于选了 Boot 4.1 与 Jackson 3。

来源项目的门禁失效也直接读到了：`legacy/pom.xml` 的 `dev` / `prod` profile 里
`checkstyle.skip`、`spotbugs.skip`、`jacoco.skip` 全部为 `true`，
且 `config/suppressions.xml` 对 `.*\.java` 全局抑制了文件长度与命名类规则。

## 本次纠偏的实际动作

- 仓库回到纯文档状态，等 `spec` / `tickets` 产出后再动代码
