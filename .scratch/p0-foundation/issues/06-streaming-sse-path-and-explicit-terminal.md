# 06: 流式 SSE 路径与显式终态

> 来源：[spec.md](../spec.md) — 用户故事 2、3、15、24

**What to build:** `stream=true` 的请求以 SSE 逐帧返回内容，流以显式发出的 TerminalEvent 后跟 `[DONE]` 收尾；任何一条流有且只有一个终态；一次处理过程中同一份上游字节只被 JSON 解析一次。

终态必须显式发出是 ADR-0006 的核心。禁止依赖响应式流的完成信号去推断结果 —— 上游完全可能在发出结束哨兵之前就关闭连接，那时的完整信号与失败长得一模一样。

**Blocked by:** 05 非流式端到端打通

**Status:** ready-for-agent

- [ ] `stream=true` 时调用方在读取过程中观察到多次帧到达，而不是等到最后收到一个拼好的整体
- [ ] 流转义过程中不丢内容：逐帧拼接后的文本与上游产出的完整文本一致（含多字节字符被切在帧边界的情形）
- [ ] 每一条流都以恰好一个 TerminalEvent 结束，其后跟上 `[DONE]`
- [ ] 终态缺失是不可能的：上游在未发出结束哨兵的情况下关闭连接时，由框架补发 Failed，而不是让流静默结束
- [ ] 终态是显式事件，不由响应式流的完成信号推断 —— 用一个「正常发完内容但刻意不发结束哨兵」的上游来销毁这种推断
- [ ] 延迟反映的是到收到终态为止的真实耗时，流式样本不再恒为零
- [ ] CHUNK_PARSE_COUNT=1：同一份上游字节在一次处理流程中只被 JSON 解析一次，由可观测计数断言
- [ ] IdleTimeout 有配置项且有合理默认值
- [ ] 流式 wire format 被纳入 golden-file 基线，包含 `[DONE]` 哨兵本身
