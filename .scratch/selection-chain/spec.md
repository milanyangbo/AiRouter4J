## Problem Statement

一次请求现在**没有"选择"这一步**：装配期那句 `upstreamProvider` bean 取的是
「默认服务的第一个启用着的实例」，而且取一次就固定下来。于是：

1. **权重、标签、启用标志是有配置、无消费者的字段。** 票 07 把它们做进了三级配置模型，
   `application.yml` 里至今写着「目前还没有消费者」。配了权重却不生效是**静默失效** ——
   系统照跑、日志干净、只是流量均分。legacy 里正是同一个毛病：`CachedWeightedSelector`
   实测只有轮询在用，**最少连接根本没有加权**，想加权的运维以为它生效了。
2. **「请求打给谁」不在一处，因此没有地方可守。** 今天非流式与流式共用同一个固定对象，
   还没分岔；但分岔的代价已经在别处付过一次 —— legacy 最贵的缺陷就是流式路径绕过治理，
   而成因正是「挑实例」散在若干个 handler 里，流式那条自己抄了一遍。
3. **后面所有作用域类能力没有挂点。** 限流的 `instance` 维度、规则的目标、失败转移换谁、
   配额的维度，全部以「这次调用选中了哪个实例」为前提。`Outcome.instanceId` 现在
   没有真实来源，它们接进来时只能先猜一个。

用户要的是：**一次请求按配置挑实例，挑的结果可解释、可复现、可被断言；流式与非流式走同一条链。**

## Solution

**一条链，落在 `routing` 一处。** 六步（ADR-0011 第 5 节，别处不再复述）：

| 步 | 做什么 | 住在哪个包 |
|---|---|---|
| ① 调用方标识 | 这次调用算谁的。粘滞与两个 hash 策略要它。**认证本身不在这里**（属 ADR-0018 / 阶段 6） | `routing` |
| ② 目标与标签 | 要哪个 Service、候选必须带哪些标签 | `routing` |
| ③ 可用性闸门 | 熔断 / 限流 / 健康把实例**排除**（ADR-0013 / 阶段 7）。排除不是降权 | `routing` |
| ④ 加权展开 | 权重 → 区间，取值一次二分查找。**独立一步，不在策略里** | `select` |
| ⑤ 粘滞 | 包装器：命中上次那个就直接用，否则交给策略 | `select` |
| ⑥ 策略 | 六个纯函数之一：`random` / `round-robin` / `least-connections` / `ip-hash` / `consistent-hash` / `latency` | `select` |

**出网不在链里**（`transport`），**失败转移也不在链里**（ADR-0013 / 阶段 7）。
判定标准：链里每一步只吃「候选 + 权重 + 上下文」这类纯输入；要出网、要读状态码的都不在六步内。

**链的输出是一个 `instanceId`，不是那个能出网的对象。** 由装配层按 id 从注册表取回实例。
于是「选得对不对」不需要先造出一个能出网的东西就能断言。

**接线**：一个 `RoutedUpstream` 取代现在那个 `upstreamProvider` bean，它同时是
`CompletionPort` 与 `StreamingCompletionPort`，**两个端口调同一个解析入口** ——
「流式绕过选择」正是要在这里被堵死，形状上就不给它第二条路。
每次请求解析一次（不是装配期固定），这样将来配置变更能落到新请求上（ADR-0010 第 5 节）。

**外部输入一律是参数，不是让策略去做 IO**（ADR-0011 (e)）：随机源、轮询光标、
活跃连接数、调用方标识、延迟样本表，全部由装配层递进来。

## User Stories

### 配置方（运维）

1. 作为一个运维，我想给同一 Service 下的两个实例配不同权重，让流量按 3:1 分配，
   这样我能让新机器先接一成流量
2. 作为一个运维，我想单独关掉一个实例做维护，希望它的请求立刻不再打到它，而且不用重启
3. 作为一个运维，我想给实例打 `gpu:a100` 这类标签，并要求某类请求只走带这个标签的实例，
   这样昂贵资源不会被普通请求占用
4. 作为一个运维，我想在配置里写一个字符串就换掉选择策略，不必改代码
5. 作为一个运维，我写了一个不存在的策略名，希望**启动就失败并列出可选的那几个**，
   而不是运行时悄悄退化成某一个
6. 作为一个运维，我想让粘滞能和任意策略组合，这样我换策略时不用重新考虑会话连续性
7. 作为一个运维，我想给粘滞配一个自定义键（例如会话 id），而不仅按调用方标识
8. 作为一个运维，我把权重写成 0 或负数时希望启动失败 —— 它是除数，
   等到选择时才炸是一个只有看过实现才知道的行为
9. 作为一个运维，我希望「这次请求打给了谁」在日志与（将来的）指标里可查，
   出问题时我能回答「为什么是它」
10. 作为一个运维，我希望延迟样本在实例被摘掉后不再影响选择，
    这样一台下线的机器不会永远占着最差那一档
11. 作为一个运维，我希望 EWMA 的 alpha、失败惩罚值、一致性哈希的虚拟节点数都是显式常量且可配，
    而不是藏在实现里

### 调用方（客户端）

12. 作为一个调用方，我希望同一会话的多次请求落到同一个实例（粘滞），而且它真的生效
13. 作为一个调用方，我在没有提供任何标识的情况下调用，希望行为是**确定的且被写清**的，
    而不是每次随机漂移
14. 作为一个调用方，我按来源哈希调用，希望同一来源稳定命中同一实例，
    且实例增减时只有一小部分键迁移
15. 作为一个调用方，我希望流式与非流式遵循同一套选择规则 —— 不要因为我要流式的就绕过选择
16. 作为一个调用方，我希望「选不出实例」时收到一个明确的错误，
    而不是被静默送到第一个实例上 —— 那种偶发的错路由最难查
17. 作为一个调用方，我希望某个实例当前不可用时，我的请求被换到另一个实例，而不是打到它上面
18. 作为一个调用方，我希望全部实例都不可用时得到一个明确失败，而不是挂住或拿到空响应
19. 作为一个调用方，我希望延迟低的实例更可能被选中，而且这个偏好会随实测延迟变化
20. 作为一个调用方，我希望一个失败率高的实例被自然降权，而不是继续均分我的流量

### 网关自身与排障的人

21. 作为网关，我希望选中的实例 id 进入 `Outcome.instanceId`，
    这样结算、指标、将来的熔断都能按实例归因
22. 作为网关，我希望「选不出实例」**不出网、也不结算** —— 判不过就在本地结束（ADR-0013 (e)）
23. 作为排障的人，我希望链上每一步都是纯的：给定输入就能复现，不需要知道当时网络怎样
24. 作为实现者，我希望新增一个策略 = 加一个纯函数类 + 在工厂登记，不动注册表与链
25. 作为实现者，我希望新增一种形态不触碰选择链 —— 形态是实例的属性，与选择无关
26. 作为排障的人，我希望「流式绕过链」这类接线错误被**两处**同时守着：
    结构规则（R4）与一条端到端断言
27. 作为网关，我希望拒绝原因能区分「服务没有启用着的实例」/「标签无匹配」/「闸门排空」，
    三种原因对应三种不同的处置
28. 作为网关，我希望链的输入里**没有**「是否流式」这一项 —— 不给分岔留入口

### 实现与测试方

29. 作为测试者，我希望给定候选与固定随机源，`random` 的结果可复现（不起端点）
30. 作为测试者，我希望轮询的权重能被**严格**断言（3:1 → 八次里 6:2），而不只是断言比例 ——
    比例对的实现也可能根本没看权重
31. 作为测试者，我希望轮询的断言与光标起点无关：光标是进程级共享状态，
    「第一次一定打给第一个实例」是一条与执行顺序有关的断言
32. 作为测试者，我希望粘滞 + 随机、粘滞 + 轮询都能稳定命中同一个实例
33. 作为测试者，我希望一致性哈希在实例增减时的迁移比例在预期量级，证明虚拟节点真的生效
34. 作为测试者，我希望注入失败样本后该实例被选中的概率下降
35. 作为测试者，我希望实例从候选里移除后，它的 EWMA 条目不再参与
36. 作为测试者，我希望除一致性哈希外，换任意策略时权重行为一致（一条断言覆盖全部策略）
37. 作为测试者，我希望一致性哈希的等价性质是「权重大的实例占的键比例 ≈ 它的权重占比」
38. 作为测试者，我希望链拒绝时抛出的异常带上 serviceId 与原因，且三种原因各有各的断言
39. 作为测试者，我希望链的断言**不起容器**也能跑完，起容器那一份只验「接到进程上了」
40. 作为测试者，我希望每条新断言都被故意破坏过一次，确认它真的会红

### 边界与失败路径

41. 作为一个配置方，我希望 Service 下所有实例都被关掉时，请求得到一个明确失败，
    而不是「找不到第一个实例」的空指针
42. 作为一个配置方，我希望标签筛完一个不剩时**拒绝**，而不是退回不筛 ——
    退回不筛等于把我写的标签静默丢掉
43. 作为一个配置方，我希望闸门把全部候选排空时**拒绝**，而不是退回全部候选
44. 作为一个网关，我希望调用方标识缺失时粘滞与两个 hash 策略的行为被显式定义并断言，
    不能静默退化成「每次换一个实例」
45. 作为一个网关，我希望粘滞记住的实例已经不在候选里时，重新走策略而不是报失败
46. 作为一个网关，我希望活跃连接数拿不到（transport 未上报）时 `least-connections`
    的行为是显式的，而不是默认 0 让所有实例看起来一样闲
47. 作为一个网关，我希望延迟样本里还没有任何样本时 `latency` 策略的行为是显式的
    （不是把未知实例当成最快）
48. 作为一个网关，我希望权重之溢出（极大权重相加）不会让区间计算溢出或静默截断
49. 作为一个网关，我希望同一个 Service 下的候选顺序是**稳定**的（配置里的顺序），
    否则同一份配置在不同进程里会挑出不同的实例
50. 作为一个排障的人，我希望热重载（阶段 3，尚未落地）之后新请求走到新实例、
    在途请求走完它开始时那一份 —— 本阶段的实现要为此留口，不要把它写死在装配期

## Implementation Decisions

**模块与包**

- `routing` —— 六步编排（①②③）、拒绝原因。`package-info.java` 要写清它不做 IO、看不到状态码
- `select` —— ④⑤⑥：加权展开、粘滞包装器、六个策略。纯函数，不做 IO、不读健康
- `config` —— 装配：把注册表、链、策略工厂、外部输入接起来；取代现有的 `upstreamProvider` bean
- `observe` —— 延迟样本：从 `OutcomeObserver` 收 `Outcome`，维护每实例 EWMA。它是策略的**输入**
- `transport` —— 活跃连接数（在途计数）的持有者，作为参数交给链
- `core` —— 不改。`CanonicalRequest` 不增字段；`SelectionContext` 是 gateway 的概念

**候选的形状**

- 候选是 `Candidate`（id / 权重 / 标签），**不是**注册表里的 `RegisteredInstance`。
  后者带着能出网的对象，而判「选择对不对」不该先造出它
- 候选顺序沿用配置里的顺序（`ServiceView` 已经这么保证），它是稳定输入的前提

**④ 加权展开**

- 权重之和是区间总长，取值一次二分查找，**不是**按权重复制候选（权重 1000 : 1 会造出 1001 个元素）
- `Arrays.binarySearch` 命中上界时要取 `found + 1`：区间不含上界。这一处第一次写错过，写在这里
- 轮询光标、随机抽签、`ip-hash` 的落点共用**这一处**加权

**⑥ 六个策略与它们的输入**

| 策略 | 需要的输入 | 说明 |
|---|---|---|
| `random` | 随机源 | 随机源**从外面注入**，于是「固定随机源 → 结果可复现」是一条真能写的断言 |
| `round-robin` | 进程级共享光标 | 光标是共享状态：断言必须写成与起点无关 |
| `least-connections` | 活跃连接数（map: instanceId → count） | 来自 `transport` 在途计数。**输入是参数，不是让策略去问 transport** |
| `ip-hash` | 调用方标识 | 落点 = `hash % 权重之和` → 走 ④ 的区间 |
| `consistent-hash` | 调用方标识 | 键环 + 虚拟节点数 ∝ 权重 |
| `latency` | 每实例 EWMA（map: instanceId → ewma） | 样本来自 `Outcome`，见下 |

- **一致性哈希是唯一一个把加权内建在策略里的**：虚拟节点数按权重分配，它本身就是加权。
  因此它**不再**叠加 ④ 的区间（叠加等于双重加权）。代价是「换任意策略权重行为一致」这条验收
  只对另外五个策略成立；一致性哈希的等价性质改由另一条断言（键比例 ≈ 权重占比）承担
- **装配期默认策略是轮询，不是随机。** 轮询可预测，于是「权重生效」能被严格断言；随机只能断言比例

**延迟样本（EWMA）**

- `ewma = alpha * sample + (1 - alpha) * ewma`，权重 ∝ `1/(1+ewma)`
- 样本来自 `Outcome.latency`（算到终态为止，ADR-0005）：成功用实际延迟，**失败用惩罚值**
- 候选里消失的实例要**惰性清理**陈旧条目，否则一台下线的机器永远占着最差值
- 样本表由 `observe` 维护（`OutcomeObserver` 是唯一观测点），**作为参数**交给策略 ——
  这样 `select` 仍然是纯函数（ADR-0003）
- alpha / 惩罚值 / 虚拟节点数：默认值待定，但必须是**显式常量且可配**，不接受藏在实现里

**⑤ 粘滞**

- 是**包装器**，包在任意策略之外（搬 `StickyLoadBalancer` 时必须保持这个形状）
- 键 = 自定义键，没有就退回调用方标识
- 命中且仍在候选里 → 直接用；不在了（被关掉、被熔断）→ 交给策略，并把新结果记回
- **调用方标识缺失时粘滞失效是显式的、被断言的行为**，不是静默退化

**① 调用方标识（阶段 4 的来源）**

- `SelectionContext` 带 `callerId`（可为空），由 Face 从入站上下文给出：
  显式请求头 → 远端地址 → 空
- 阶段 6 认证接上后来源换成认证结果，**链不变**
- `SelectionContext` **不含**「是否流式」

**拒绝**

- `NoUsableInstanceException` 带 serviceId 与原因，三种原因各有各的措辞：
  没有启用着的实例 / 标签无匹配 / 闸门排空
- 三种都**拒绝**，不退回不筛、不退回全部候选、不静默挑第一个
- 由 Face 在边界上收口成一个错误响应：不出网、不结算

**接线**

- `RoutedUpstream` 取代 `upstreamProvider` bean，同时是两个端口（**只声明一个 bean** ——
  容器按运行期类型匹配候选，拆成两个会让注入任何一侧都匹配到两个候选）
- 两个端口调**同一个**解析入口；每次请求解析一次
- 「启用」由装配层筛，不在链里：链不知道实例有没有被关掉，那是配置的事
- 策略按名取（`airouter.routing.strategy`），未知名 → **启动失败并列出已登记的名字**
  （与形态工厂报「没有对应的构造器」时列出已登记形态同一理由）

**结构规则**

- R4 的生产侧断言随 `routing` 包开放接管（ADR-0003 第 2 节已写明这条交接）
- `routing` 与 `select` 登记进 `RulesCoverNonEmptyPackagesTest`：
  只有 `package-info.java` 的包不算「规则已覆盖」

## Testing Decisions

**什么算好测试**：只测外部行为 —— 给链一组输入、断言它选出的 id；或者发一次请求、
断言它落到了哪个录制器。**不测**「第 ④ 步被调了一次」「某个策略类被构造」这类内部步骤，
那是抄实现（testing.md 判据三）。

**两道接缝**（已与用户确认）：

1. **链 / 策略入口**（`airouter-gateway` 单测，`@Tag("unit")`）—— 主接缝。
   构造候选 + `SelectionContext` + 注入的随机源 / 活跃连接数 / 延迟样本 → 断言选中的 id。
   不起容器、不起端点。覆盖：六步顺序、加权（含二分上界）、六个策略、粘滞组合、
   EWMA 降权与惰性清理、三种拒绝
2. **HTTP 入口**（`airouter-app` 集成，`@Tag("integration")`，两个**录制器**当两个实例）——
   只验「规则真的接到进程上了」：流式与非流式走同一条链、关掉的实例不被打到、
   权重在真实请求上生效、策略名配置真的被读到。**不把单测重抄一遍**（testing.md 六·3）

第三项 R4 生产侧断言属既有门禁基础设施，不算新接缝。

**先验（照着写，不另起形状）**：`StreamingEndToEndTest` / `GoldenWireContractTest` 用
`RecordedUpstream`（字节块一级可控，能报告收到几次请求）；`LocalProfileTest` 用手起的上下文。
轮询相关的断言写成**与光标起点无关**：1:1 看交替，3:1 取八次 = 两整轮。

**纪律**

- 每条新断言故意破坏一次、确认会红，再恢复（ADR-0008）
- **探红恢复不用 `git checkout`**（它会把未提交的改动一起退回 HEAD）。先 `cp` 备份到 `/tmp`，跑完 `cp` 回来
- 预算（`docs/agents/testing.md`）：每模块 ≤10 个测试文件（最多 20）、每文件 ≤20 个方法、
  行覆盖率 ≥60%。app 现在 11 个（已顶破软上限一个），新增端到端那一份**先找合并目标**
- 行覆盖率是**全项目一个数**，不给单模块设闸 —— 接缝在 HTTP 入口，一个模块的链路
  往往由另一个模块的测试跑过

## Out of Scope

- **认证与租户标识**（阶段 6 / ADR-0018）：本阶段只取标识，不做校验、不建租户
- **熔断、失败转移、限流、健康登记**（阶段 7 / ADR-0013）：第 ③ 步闸门本阶段**恒开**，只留接口；
  它排空时拒绝的行为要被断言（那时才有真正会排空它的东西）
- **规则路由**（阶段 8 / ADR-0012）：`requiredTags` 本阶段来自服务级配置，不是规则匹配结果
- **热重载与配置版本**（阶段 3 尚未落地的那一半，ADR-0010 第 5、6 节）：
  链每次请求解析是为它留口，替换注册表不在本 spec
- **多副本下的光标与粘滞共享**（阶段 13）
- **控制台上的策略配置页面**（阶段 16）
- **新增形态**（阶段 12）：本 spec 不引入也不假设第二种形态

## Further Notes

**两处文档张力（本 spec 记一笔，不在此处擅自裁决）**

1. `GLOSSARY.md`「选择链」那一节仍写着**旧六步**（含「出网调用」与「失败转移」），
   与 ADR-0011 第 5 节（唯一定义处）冲突。按本次会话已定的方向（出网是 transport、
   失败转移属阶段 7，都不在链里），**应当改 GLOSSARY 这一处**；
   术语表自己写着「两处冲突以本表为准，并去改 ADR 那一处」，
   因此这一条要由 `domain-modeling` 收口，不要两边各改一半
2. `GLOSSARY.md` 说注册表持有「延迟样本」，而 ADR-0003 要求 `select` 是纯函数。
   本 spec 的取法是：样本由 `observe` 从 `Outcome` 维护、作参数交给策略，
   `select` 因此仍然纯。术语表那一句待裁决

**上一轮被回退的实现留下了可复用的实测结论**（`9f9048f` / tag `baseline-8`，已被 revert；
结论留在 `.workbuddy/memory/MEMORY.md`「已回退的两块」）：加权二分的**上界处理**、
轮询光标是**进程级共享状态**（e2e 断言要与起点无关）、`RoutedUpstream` 存注册表会撞
SpotBugs `EI_EXPOSE_REP2`（收窄成 JDK 的 `Function<String, ServiceView>` 即可）、
两个录制器的写法。重做时从那儿起，不用重踩。

**一个已知的取舍**：粘滞键与 `ip-hash` / `consistent-hash` 的键默认都是调用方标识，
三者组合时前两者会让第三个失去意义（粘滞已经把同键固定住了）。这不是错误，
但应在配置文档里写清「粘滞 + 一致性哈希」这种组合的实际行为是「键变时才换实例」。
