# 09: 策略工厂、配置与粘滞包装器

**What to build:** 把「用哪个策略」从代码变成配置，并把**粘滞**做成包装器。

- **策略工厂**：按名取策略（`airouter.routing.strategy`）。
  未知名 → **启动失败并列出已登记的名字** —— 与形态工厂报「没有对应的构造器」时
  列出已登记形态同一理由：让运维自己改对一个字，而不是去翻代码
- **粘滞是包装器，不是第七种策略**（ADR-0011 (c)）。legacy 的 `StickyLoadBalancer`
  就是包装器，搬的时候必须保持这个形状 —— 搬成策略会丢掉「粘滞可与任意策略组合」这个性质

**Status:** pending

## Acceptance criteria

- [ ] `SelectionStrategyFactory` 按名取策略；**未知名 → 启动失败并列出已登记的名字**
- [ ] `airouter.routing.strategy` 绑定与校验：未知值**启动失败**（与上面同一条判据的两处入口，
      别只在一处拦）
- [ ] 粘滞**包在任意策略之外**，键 = 自定义键，没有就退回 `callerId`
- [ ] 粘滞命中、且它仍在候选里 → 直接用；不在了（被关掉、被第 ③ 步排除）→ 交给策略，
      并把新结果记回（不是报失败）
- [ ] **`callerId` 缺失时粘滞失效是显式且被断言的行为** —— 不许静默退化成「每次换一个实例」，
      那正是 legacy 加权那种静默失效的同一形状
- [ ] 粘滞 + 随机、粘滞 + 轮询 都能稳定命中同一实例（两条接缝各一条断言）
- [ ] 粘滞表**有界 + 惰性清理**：键的生命周期由调用方决定，无限增长会撑爆内存，
      而一个永不清理的表会让「粘滞到哪个实例」变得无法解释
- [ ] 六个名字**逐步**登记进工厂：本票登记票 08 的两个，票 10 补四个。
      「未知名列出已登记名」那条断言因此随登记数变化 —— 它列的是**当时**登记的名字

## Known gaps（本票不做）

- 其余四个策略与 EWMA 延迟样本 → 票 10
- **粘滞键的跨副本共享** → 阶段 13（多副本）。本票是进程内表，多副本下「粘滞」只在单副本内有意义
- 粘滞状态的查询与清除（管理面 / 控制台）→ 阶段 16
- 自定义键**从哪来**（某个请求头、会话 id）本票只定义接口，取值来源随认证（阶段 6）明确

## 落点

| 文件 | 内容 |
|---|---|
| `select/StickySelector` | 包装器：命中就用，否则委托给被包的那个策略 |
| `select/SelectionStrategyFactory` | 名字 → 策略的登记处；未知名报错时列出已登记的名字 |
| `config/RoutingProperties` | `airouter.routing.strategy`（+ 粘滞键与开关）的绑定与校验 |
| `config/UpstreamConfiguration` | 装配：工厂 + 粘滞包装 + 配置校验接进启动期 |

## 测试（同票 08 的两条接缝）

1. **单元接缝**：粘滞 + 随机、粘滞 + 轮询 各一条；被粘滞的实例从候选里消失后重选；
   `callerId` 缺失时的行为；未知名策略启动失败并列出已登记名
2. **HTTP 入口**：配一个策略名 + 粘滞，连续两次请求落到同一个录制器；
   关掉那个实例后请求换到另一个（而不是失败）
